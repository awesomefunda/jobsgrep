# JobsGrep

**[jobsgrep.com](https://jobsgrep.com)** — Self-hosted job aggregator. Pulls open roles from Greenhouse, Lever, Ashby, SmartRecruiters, Adzuna, HN Who's Hiring, YC companies, USAJobs, and more into a segmented Excel workbook (role tabs + a Level column). Download it, paste it into Claude/ChatGPT with your resume, and let your own LLM rank the jobs for you.

## Deploy to Vercel

[![Deploy with Vercel](https://vercel.com/button)](https://vercel.com/new/clone?repository-url=https://github.com/yourusername/jobsgrep)

```bash
# 1. Generate pre-seeded job data locally (run once before each deploy)
python scripts/generate_seed.py

# 2. Commit the seed data
git add data/seed/
git commit -m "seed: pre-scored job data"

# 3. Deploy
vercel deploy
```

**Required env vars on Vercel** (set in Vercel dashboard):
```
GROQ_API_KEY=gsk_...         # or GEMINI_API_KEY
JOBSGREP_MODE=PUBLIC          # auto-set by vercel.json
```

Vercel cold starts load the pre-seeded scored jobs from `data/seed/` instantly.
Common searches (Software Engineer, Bay Area, Remote) return results in ~2 seconds.
Live searches on uncached queries take up to 60 seconds — Vercel Pro recommended.

## Quick Start

```bash
cd jobsgrep
cp .env.example .env        # add GROQ_API_KEY at minimum
pip install -e .
python scripts/seed_companies.py   # optional: pre-seed 50 known company ATS slugs
jobsgrep serve               # → http://localhost:8080
```

Or with Docker (auto-validates config and generates tokens on first run):

```bash
cp .env.example .env        # edit as needed
docker compose up
```

| Variable | Required | Description |
|---|---|---|
| `GROQ_API_KEY` | Recommended | LLM for parsing odd queries on a cache miss (no scoring) |
| `GEMINI_API_KEY` | Optional | Alternate parser provider — 1,500 req/day free tier. Used first if set. |
| `JOBSGREP_MODE` | No (default: `LOCAL`) | `LOCAL` \| `PRIVATE` \| `PUBLIC` |
| `JOBSGREP_ACCESS_TOKEN` | PRIVATE mode | Bearer token. Auto-generated by Docker if not set. |
| `MIN_FIT_SCORE` | No (default: `0.7`) | Minimum score (0–1) to include a job in the report |
| `USAJOBS_API_KEY` | No | Register free at [developer.usajobs.gov](https://developer.usajobs.gov) |
| `ALLOW_SCRAPE` | No (default: `false`) | Force-enable JobSpy scraping in non-LOCAL modes |
| `PORT` | No (default: `8080`) | Server port |

See `.env.example` for the full list.

## Deployment Modes

Controlled by the `JOBSGREP_MODE` environment variable:

| Mode | Auth | Scraping | Caching | Use case |
|---|---|---|---|---|
| `LOCAL` | None | Allowed | 1 hour | Personal laptop use |
| `PRIVATE` | Bearer token | Allowed | 1 hour | Your own server / Cloudflare Tunnel / ngrok |
| `PUBLIC` | IP rate limiting | **Disabled** | **Disabled** | Public VPS / cloud deploy |

Scraper sources (JobSpy, Levels.fyi, TeamBlind) are **compile-time gated** — calling them in `PUBLIC` mode raises an error before any network call is made. `LOCAL` and `PRIVATE` both allow scraping since there's no multi-user IP-ban risk.

## LLM Providers

JobsGrep uses a unified provider chain. The first available key wins:

1. **Gemini 2.0 Flash** — set `GEMINI_API_KEY` (1,500 req/day free, recommended)
2. **Groq Llama 3.3 70b** — set `GROQ_API_KEY` (fast, generous free tier)
3. **Groq Llama 3.1 8b** — automatic fallback if 70b is rate-limited

Keys are used for NL query parsing only (job ranking happens on the user's machine with their own LLM). Adding a new provider (OpenAI, Ollama, etc.) requires only a new function in `jobsgrep/llm.py`.

## Excel Report — Built-in Tracker

The generated `.xlsx` is designed to be your full job search tracker, not just a reference list.

**Sheet 1: Job Tracker**
- Left side (dark header): auto-filled by JobsGrep — rank, score, company, title, location, salary, URL, matching/missing skills, red flags
- Right side (teal header): your tracking columns — **Status** (dropdown), Applied Date, Outreach Sent, Response, Phone Screen, Interview, Offer, Notes
- Status pre-filled as `New` for every row — just change it as you progress
- Freeze panes keep Company + Title visible while scrolling into tracking columns

**Sheet 2: All Jobs Found** — complete reference list before scoring

**Sheet 3: Search Summary** — original query, parsed interpretation, sources searched, jobs per source

## Search History

```
GET    /api/history    List past searches

```

## ATS Slug Discovery & Dynamic Ingestion

Expand the list of companies searched by running the built-in CLI commands:

```bash
# 1. Probe up to 500 YC hiring companies automatically
jobsgrep discover --limit 500

# 2. Probe a list of custom company names from a flat file (one name per line)
jobsgrep discover --seed-file my_companies.txt

# 3. Manually register a company with a known Greenhouse/Lever/Ashby/Recruitee/Workable slug
jobsgrep add-company "Linear" ashby linear
jobsgrep add-company "Hightouch" greenhouse hightouch

# 4. Manually register a custom Workday company
jobsgrep add-company "Nvidia" workday --host nvidia.wd5.myworkdayjobs.com --tenant nvidia --site NVIDIAExternalCareerSite
```

Mappings are cached in `~/.jobsgrep/company_ats_mapping.json` and are preserved on runs. All dynamic targets are automatically queried during the weekly `run-prefetch` crawl.

## Architecture & Performance

JobsGrep separates **data collection** (done ahead of time, in bulk) from
**ranking** (done by the user's own LLM). The server never scores jobs.

### How it works

```
LOCAL (you)
  jobsgrep run-prefetch  → fetch the whole corpus once from all sources
                           (query-independent; each board fetched a single time)
  jobsgrep push          → upload the corpus to production
  jobsgrep export        → segmented Excel (role tabs + Level + ranking prompt)

PRODUCTION (a user search)
  parse query (regex; LLM only on a cache miss)
        │
        ▼
  match against the cached corpus ──hit──▶ return instantly (0 scoring LLM calls)
        │ miss
        ▼
  "I don't have that data" — no live scraping
```

The corpus is fetched **once** rather than per query, so a board like Stripe's is
pulled a single time instead of once for every role searched. Ranking is offloaded
to the user's LLM (paste the sheet + your resume), so there is no scoring cost on
the server at all.

### LLM usage

| Step | LLM? |
|---|---|
| Corpus prefetch (local) | No — pure HTTP fetch |
| Segmented export (local) | No — title heuristics only |
| Production search | Only to **parse** an odd query on a cache miss |
| Ranking | On the **user's** machine, with their own LLM + resume |

### Cache warm-up workflow

Prefetch fetches the **entire tech-job corpus in one pass** (every board/thread,
once — no per-query re-fetching) and writes it to the local cache. There is no
scoring step: production serves keyword/title matches straight from this corpus.

```bash
# Step 1: fetch the full corpus locally (no LLM, no scoring)
jobsgrep run-prefetch

# Step 2: push the corpus to your production server
jobsgrep push --server https://jobsgrep.com --token <JOBSGREP_ACCESS_TOKEN>
```

In production a user's query is parsed (regex first, LLM only on a cache miss),
matched against the corpus, and returned instantly. If nothing matches, the app
reports that it has no data for that query rather than scraping live.

On the server, the prefetch worker re-runs automatically every 6 hours (configurable via `PREFETCH_INTERVAL_HOURS`).

### Downloadable job packs (segmented sheets)

`jobsgrep export` turns the cached corpus into a single Excel workbook designed to
drop straight into an LLM with your resume — no server-side scoring:

```bash
jobsgrep run-prefetch          # populate the corpus
jobsgrep export --out ./packs  # build the workbook
```

The workbook contains:
- a **Start Here** tab with ready-to-paste ranking prompts and per-tab counts,
- one tab **per role family** (Software Engineering, Data & ML, Infrastructure &
  DevOps, Security, Design, Engineering Management, Product Management, …), each
  with a **Level** column (Intern → Junior → Mid → Senior → Staff → Principal →
  Manager → Director → VP → Executive) so you can filter by seniority in Excel,
- an **All Jobs** master tab.

Ranking happens on your machine: open the role tab, paste the rows + your resume
into Claude/ChatGPT, and use the bundled prompt to get a personalized shortlist.

## CLI Commands

```bash
jobsgrep serve                                    # Start web server
jobsgrep search "Staff SDE remote Python"         # CLI search → Excel file
jobsgrep run-prefetch                             # Fetch the full job corpus → cache (no LLM)
jobsgrep export                                   # Corpus → segmented Excel (role tabs + Level column)
jobsgrep export --fetch --out ./packs            # Fetch fresh, then export to ./packs
jobsgrep discover [--limit 500]                   # Probe YC companies for ATS slugs
jobsgrep sources                                  # List enabled sources for current mode
jobsgrep health                                   # Test all source APIs
jobsgrep add-company <name> <greenhouse|lever|ashby> <slug>

# Push locally-scraped jobs to a remote JobsGrep server
jobsgrep push --server https://jobsgrep.com --token <token>
jobsgrep push --server https://jobsgrep.com --token <token> --query "Software Engineer"
jobsgrep push --server https://jobsgrep.com --token <token> --dry-run
```

The `push` command reads your local job cache (`~/.jobsgrep/job_cache/`) and uploads it to a remote server via `POST /api/import`. Remote users then get instant results from the pre-populated cache instead of waiting for live scraping.

## Legal

This tool queries **public APIs only** (except JobSpy in LOCAL mode). Every request uses an honest `User-Agent` header. Source rate limits are respected with a 50% buffer. An append-only audit log is written to `~/.jobsgrep/audit.log`.
